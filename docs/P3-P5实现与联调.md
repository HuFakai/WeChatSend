# P3–P5 实现与联调说明

本文对应当前代码，不替代《分阶段开发计划》。P3/P4/P5 的依赖服务没有配置时，P1/P2 邮件发送链路仍可独立运行。

## P3：导入与动态内容

Web 和小程序都提供以下入口：

- 好友管理：粘贴备注、导入 CSV/XLS/XLSX，或上传 PNG/JPEG/WEBP 截图。
- 截图识别只返回候选备注，必须在“批量添加好友”确认后才入库；重复备注会跳过并返回数量。
- 内容变量：CSV/XLS/XLSX 第一列作为候选值，导入前会拒绝公式单元格，不执行表格公式。
- `random_quote` 和 `warm_greeting` 是平台内置、按任务种子稳定生成的变量。
- 天气等实时内容不写死供应商。在管理后台创建外部 API，可配置请求头、请求参数和多个 JSON 响应路径，例如 `data.weather.text`、`data.weather.temp`，分别映射为 `{{weather_text}}`、`{{weather_temp}}`。任务提交时请求一次并冻结结果；请求失败或响应路径取不到值会阻止发送。

对应接口：

```text
POST /api/v1/imports/friends/file/parse
POST /api/v1/imports/friends/file/commit
POST /api/v1/imports/friends/image/parse
POST /api/v1/imports/variables/file/import
```

图片会短暂以 base64 进入服务端请求，不写入数据库或永久文件。生产环境建议限制 API 网关请求体大小；如果以后需要审计，再增加带过期时间的私有对象存储。

## P4：AI 与行业内容

管理员先在 `/admin` 添加 OpenAI 兼容通道和模型。`APP_ENCRYPTION_KEY` 必须配置，API Key 只保存加密文本，列表接口不返回明文。

AI 接口：

```text
GET  /api/v1/ai/options
POST /api/v1/ai/generate
POST /api/v1/ai/task-draft
GET  /api/v1/mini/ai/options
POST /api/v1/mini/ai/generate
POST /api/v1/mini/ai/task-draft
```

`TASK` 模式只创建 `TaskDraft`，不会创建 `TaskMessage`，也不会发邮件。用户仍需选择发送账号、好友、间隔和时间，再走任务预览/确认。

小程序的三个 AI 功能由管理员分别控制，关闭后小程序不会显示对应工作方式，服务端也会再次拒绝调用：

- `mini_ai_copy`
- `mini_ai_template`
- `mini_ai_task`

行业种子执行一次即可：

```bash
npm run db:deploy
npm run content:seed
```

脚本按通用销售、零售门店、家居建材、汽车销售与售后四类生成 120 条候选模板。同名模板不会重复插入，也不会覆盖管理员后续编辑的内容；发布前仍需在“内容库审核”逐条检查。

## P5：小程序身份与扫码支付

小程序不再要求用户填写平台用户名和密码：

1. 启动时调用 `wx.login`，服务端调用微信 `jscode2session`。
2. 服务端根据 openid 查询已有用户；没有绑定记录时进入授权登录页。
3. 用户点击授权按钮后调用 `wx.getUserProfile`，将昵称和头像 URL 与 openid 一起提交。
4. 已有 openid 更新资料并登录，新 openid 创建平台用户；`session_key` 不返回客户端。

服务端接口：

```text
POST /api/v1/auth/miniprogram/silent
POST /api/v1/auth/miniprogram/login
POST /api/v1/auth/miniprogram/bind
```

支付是“扫码进入小程序 + 小程序 JSAPI 支付”，不是把商户密钥放入二维码：

1. Web/API 调用 `POST /api/v1/payments/qr` 创建待支付订单并返回小程序码图片。
2. 用户扫码进入 `pages/pay/index`，小程序通过 `scene` 查询订单。
3. 登录/授权后调用 `POST /api/v1/payments/orders/:id/checkout`。
4. 服务端向微信商户 API 发起 JSAPI/小程序下单，返回 `wx.requestPayment` 所需参数。
5. 微信调用 `POST /api/v1/payments/notify`；服务端校验平台证书签名、AES-256-GCM 解密，再更新订单状态。小程序支付成功后会轮询订单状态，不能只依赖前端回调判断支付是否成功。

订单状态查询接口：

```text
GET /api/v1/payments/orders/:id
```

小程序收到支付回调后通过该接口确认服务端订单状态；只有状态为 `SUCCESS` 时才展示支付成功。

支付配置：

```text
WECHAT_MINI_APPID
WECHAT_MINI_SECRET
WECHAT_PAY_MCH_ID
WECHAT_PAY_SERIAL_NO
WECHAT_PAY_PRIVATE_KEY
WECHAT_PAY_API_V3_KEY
WECHAT_PAY_PLATFORM_CERT
WECHAT_PAY_NOTIFY_URL
```

小程序后台必须把部署域名加入 request 合法域名；回调地址必须是公网 HTTPS。金额使用人民币分，支付订单默认 30 分钟过期。

官方参考：

- [微信小程序登录 wx.login](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/login.html)
- [微信支付：小程序调起支付](https://pay.wechatpay.cn/doc/v3/merchant/4012791898)
- [微信支付：JSAPI/小程序下单](https://pay.wechatpay.cn/doc/v3/merchant/4012791897)

## 推荐验收顺序

1. 不配置 AI/微信支付，只执行迁移，确认 P1/P2 登录、好友、任务和 Worker 不受影响。
2. 配置 `APP_ENCRYPTION_KEY`，添加一个 OpenAI 兼容模型，Web 生成文案和任务草稿。
3. 打开小程序，确认已绑定 openid 的用户不再看到账号密码登录；清理测试账号后验证授权创建。
4. 导入一个含公式的表格，确认被拒绝；再导入纯值 CSV，确认预览后入库。
5. 配置截图模型，确认截图识别结果必须手动确认后才增加好友。
6. 最后配置微信支付商户参数，先用小额测试订单验证下单、调起、回调验签和订单状态，不要用生产订单反复重试。
