# WeChatSend 分阶段开发计划

> v1.2 · 2026-09-08
> 已选 UI：A 黑白极简。P1 MVP 已完成真实链路验证，P2 客户与内容功能已实现；P3/P4 基础能力与 P5 小程序身份/支付链路已进入联调。
> 本文是阶段范围与顺序的唯一依据，替代《项目开发方案》中原先“全部功能完成才交付首版”的安排；技术架构及邮件规则继续沿用。

## 1. 交付方式

先交付可真实使用的 MVP，再按阶段增加能力。每个阶段都明确功能、页面、依赖和验收；本阶段闭环通过后再推进下一阶段，避免一次开发所有模块。

Web 与小程序在每个发布阶段功能对等，不把小程序全部推迟到最后。实现时可以先完成共用接口，再依次实现两端，但阶段验收要求两端都能完成同一套业务操作。网页登录扫码与小程序确认等平台特有交互采用对应入口。

用户已选择黑白极简，但尚未确认所有页面。先设计并确认 MVP 所需页面，确认后启动 MVP 开发；后续模块在各自阶段补设计及确认，不必在 MVP 前画完远期所有页面。

## 2. 阶段总览

| 阶段 | 版本 | 目标 | 本阶段新增 |
| --- | --- | --- | --- |
| P0 | UI 确认 | 确定 MVP 界面及操作流程 | A 风格规范、双端 MVP 页面、关键异常状态 |
| P1 | v0.1 MVP | 从平台创建任务到 iPhone 微信发送跑通 | 账号密码、发送账号、好友、手工文案、立即/单次定时、间隔、邮件记录 |
| P2 | v0.2 客户与内容 | 减少重复选人和重复写文案 | 分组/标签、模板/收藏、基础变量、草稿/复制任务 |
| P3 | v0.3 批量与动态内容 | 提高导入和内容组织效率 | 多模态截图导入、Excel/CSV、天气、随机语录/问候 |
| P4 | v0.4 AI 与行业库 | 加速生成内容和任务 | AI 文案/模板、AI 任务草稿、内容管理后台、行业模板扩充 |

上述阶段不另设账号、好友或任务人数产品上限。所有版本都采用分页、分批处理及发信服务限流。

## 3. P0：黑白极简与 MVP 页面

采用 [A 风格图](../UI/01-A-黑白极简.png) 的白底、浅灰导航、细边框、黑色主按钮、紧凑列表和克制图标。状态同时使用文字/图标辨识；错误不能只靠颜色表示。Web 使用 React + shadcn/ui，小程序以原生组件复现同一视觉规范。

待设计的 MVP 页面组：

1. 账号密码登录：输入、校验、登录失败、退出。
2. 工作台：简要任务摘要、创建任务及配置入口，不做复杂图表。
3. 微信发送账号：列表、新增/编辑、自己的接收邮箱、选填主题、验证和配置教程、测试、停用。
4. 好友管理：按账号切换、手工添加/编辑、批量粘贴预览、重复提示、搜索、多选、停用。
5. 新建任务：手工文案 → 多选账号和各账号好友 → 间隔及时间 → 预览确认。
6. 任务列表与详情：邮件进度、逐条结果、错误原因、取消剩余项。

每组同时设计 Web 和小程序，补充空、加载、失败状态；任务补充结果不确定及部分取消。MVP 导航只展示已交付功能，不放不可用的模板、变量或 AI 按钮。

**完成条件：** 用户确认黑白极简下的双端 MVP 页面及流程，字段与实际邮件协议一致。风格选择不等于页面确认；本次不自动开始业务开发或生成全部页面图。

## 4. P1：v0.1 MVP，真实链路闭环

### 包含功能

| 模块 | 最小交付 |
| --- | --- |
| 登录 | 两端账号密码登录/退出、基本会话、用户数据隔离；受邀内测账号由部署管理命令创建 |
| 发送账号 | 多账号管理、用户邮箱、主题默认 WeChatSend、账号默认间隔、停用、邮箱验证、配置教程和测试 |
| 好友 | 手工添加/编辑、分隔符批量粘贴及确认、按账号备注唯一、搜索多选、停用；暂不做分组标签 |
| 文案 | 输入或粘贴纯文本；一项任务统一文案；不引入模板/变量/AI |
| 任务 | 多选账号、分别多选好友、预览、立即发送、单次定时、取消未发送部分 |
| 间隔 | 固定值或范围，默认 10～15 秒、下限 10 秒；任务按账号可覆盖；同账号跨任务串行 |
| 邮件 | 每位好友一封标签邮件、平台发信适配器、独立 Worker、持久队列 |
| 结果 | 待处理、发送中、邮件已发送、明确失败、结果待核实、已取消/跳过；查看逐条错误 |
| 运行 | 本地一键启动说明、邮件沙箱、环境变量示例、迁移、基本健康检查及脱敏日志 |

单次定时保留在 MVP：它已经是确定的核心发送方式，与持久调度共用基础能力。周期任务不在此范围。

MVP 不做公开注册/找回密码 UI、自建模板、变量、截图 AI、文件导入、AI 文案、行业后台、小程序微信身份登录或扫码登录。需要恢复内测账号时通过受控管理命令操作，不为 MVP 先建用户管理后台。

### 开发顺序

1. 工程骨架与数据库：Web/API/Worker/小程序结构、认证、会话和 owner_id 隔离。
2. 账号和好友：接口与两端页面、唯一性、批量预览、邮箱验证和停用。
3. 任务和投递：名单与文案快照、确认提交、单次调度、消息展开、串行间隔、发送记录。
4. 双端闭环：任务列表、逐好友明细、取消与错误反馈，邮件沙箱验证。
5. 真实联调：指定测试账号、接收邮箱和 iPhone，核对实际微信结果并记录设备条件。

### MVP 不能省略的基础

- 用户提交幂等、任务与 Outbox 同事务、消息展开唯一约束，避免双击或恢复时重复建消息。
- 同账号执行槽、next_allowed_at、发送尝试记录；取消与配置变更在发信前复核。
- 邮件结果不确定时不自动重发；明确未接受的临时失败才有限重试。
- 邮件正文和接收备注在提交时冻结；任务提交后不可直接编辑。
- 用户隔离、密码哈希、会话验证、服务端输入校验，日志不暴露邮箱口令或密钥。

MVP 先实现实际使用的实体：users、sessions、wechat_accounts、邮箱验证、friends、tasks、task_recipients、task_account_settings、task_messages、delivery_attempts、account_dispatch_state、outbox。模板、变量、AI、对象存储等表和服务随阶段增量添加，不提前搭空模块。

### 验收门槛

1. 两端以同一平台账号登录，能管理相同发送账号和好友；另一用户无法读写这些数据。
2. 选择两个微信发送账号及各账号好友，正确拆成一好友一邮件，没有跨账号串人；同账号重名被拒绝。
3. 立即与单次定时任务均可处理；同一账号两个任务共用间隔，不同账号可以并行。
4. 模拟重复提交、Worker 重启、队列消息重复，任务不会重复展开，积压恢复不会瞬时突发投递。
5. 明确拒绝、结果未知、部分取消显示正确；未知项不会自动重新发送。
6. 真实邮件经 iPhone 快捷指令让至少一位有效测试好友收到正确文本；客户端退出后服务器定时仍工作。
7. 用有效好友、不存在好友、另一有效好友的独立邮件进行设备测试，记录后续触发结果；如果后续被设备阻塞，明确记录并修正使用流程后再判断是否满足内测需求。

真实链路验收属于 MVP，不留到所有高级功能做完。模拟邮件通过只算开发测试；缺少发信配置、测试 iPhone 或小程序 AppID 时标为相应联调未完成，不能宣称双端 MVP 已跑通。锁屏动态收件人限制不作为已解决能力。

## 5. P2：v0.2，客户分组与可复用内容

**实现状态（2026-09-08）：** 已完成 API、数据库迁移、Web 与微信小程序页面。正式环境执行 P2 迁移后进入双端验收。

**新增：** 好友分组和标签、多组去重选择；我的模板、少量精选平台模板、收藏和复制；日期/时间/星期/好友称呼；自定义固定/随机/顺序列表变量（手工录入及粘贴）；任务草稿、复制历史任务及修改后重新确认。

**页面：** 好友分组标签、模板列表/详情/编辑、变量列表/编辑、任务变量预览及草稿列表，两端完整实现。

**实现要求：** 冻结模板和候选值版本、任务稳定好友顺序、随机种子；重试不改变最终文案。顺序变量每个任务从第一项开始。预览返回内容指纹，正式提交时重新校验，变量或名单在两步之间变化时要求重新预览。平台精选模板可先作为受版本管理的种子数据，不先搭完整编辑后台。

**验收：** 分组与手动选择重复好友只发一条；未知变量和空候选值阻止提交；预览与最终静态文案一致；模板后来修改不改变已提交任务；两端可互相接续编辑草稿。

## 6. P3：v0.3，导入与动态内容

**实现状态（2026-09-08）：** 已完成表格解析导入、截图多模态候选识别、导入确认、内置随机语录/温馨问候；天气等外部动态内容通过管理员配置 API 映射为一个或多个变量。Web 与小程序均有入口，真实 AI/天气供应商仍需配置后验收。

**新增：** 多模态 AI 好友截图识别、候选纠正及导入确认；自定义变量 .xlsx/CSV 导入与错误报告；指定地区天气、平台随机语录和温馨问候。

**页面：** 上传及解析进度、候选预览、重复和错误行、变量文件导入、地区选择及动态内容预览，两端完整实现。

**新增依赖：** 多模态模型及管理员配置的外部 API。当前图片在请求体中短暂处理，不落盘；后续如需要审计再接私有文件存储和清理策略。MVP 和 P2 不依赖这些服务即可工作。

**验收：** 识别结果确认前不入库；模糊备注不能擅自补全；重复导入确认幂等；Excel/CSV 不执行公式；天气失败有明确状态，不发送占位符；重试用已保存内容；小程序也能完成文件选择和导入，不要求转到 Web。

## 7. P4：v0.4，AI 助手与行业内容

**实现状态（2026-09-08）：** 已完成 OpenAI 兼容通道/模型管理、密钥服务端加密、小程序 AI 开关（前端隐藏 + 服务端校验）、Web/小程序文案/模板/任务草稿入口、平台模板审核启停后台，以及可重复执行的 120 条行业话术种子脚本。种子内容仍需业务人员逐条审核后再作为正式营销资产使用。

**新增：** AI 文案、润色、带变量模板；自然语言生成发送任务草稿；内容审核、发布、停用、行业分类后台；完善通用销售、零售、家居建材、汽车销售/售后话术。

**页面：** AI 助手、候选文案、结构化任务草稿及缺失信息、管理员模板编辑/审核，两端同一角色能力一致。

**内容目标：** 120 条候选种子模板，四个类别各 30 条，每类覆盖活动通知、节日问候、降价提醒；执行 `npm run content:seed` 后由管理员审核、修改、停用，不能把自动生成种子直接视为已审核内容。

**验收：** AI 只能返回草稿，用户确认才投递；存在歧义的账号/好友/时间不擅自执行；价格等事实由用户提供；只有审核发布的模板对普通用户可见。

## 8. P5：v1.0，登录与发布完善

**当前实现状态（2026-09-08）：** 已完成小程序 `wx.login`、服务端 code2Session、openid 查询/自动创建账号、昵称头像授权更新；已完成扫码进入小程序后查询订单、授权身份、调起微信支付 V3 JSAPI、服务端回调验签及支付结果轮询。Web 扫码登录、公开注册/找回密码、通知中心和正式支付资质联调仍需后续完成。

**新增：** 小程序微信登录与已有账号绑定、Web 小程序扫码确认登录；公开注册/找回密码、个人设置、站内通知/通知记录；优化配置引导及可恢复的用户操作。

**页面：** 注册/恢复账号、身份绑定、扫码待确认/过期/拒绝、设置与通知；平台特有交互有对应流程，业务功能不删减。

**验收：** 绑定不产生两份用户数据；票据短期、绑定浏览器、一次性兑换；同角色双端功能逐项对齐；全阶段回归、备份恢复演练、部署和运行手册完成。

基础日志、用户隔离、真实设备联调和可靠投递在 P1 就有，P5 进行完善和扩量验收。收费支付、团队协作、周期任务、图片文件发送、微信送达回执不自动纳入 P5，另行评估。
