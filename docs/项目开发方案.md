# WeChatSend 项目开发方案

> v1.2 · 2026-09-07 · 已选 A 黑白极简，先确认 MVP 页面，再分阶段开发
> 依据：[项目介绍](./项目介绍.md)、[标签邮件协议与快捷指令](./标签邮件协议与快捷指令.md)。P1 MVP 已按本方案实现，正在进行线上部署与真机验收。

阶段范围以 [分阶段开发计划](./分阶段开发计划.md) 为准。本文页面、实体及接口为完整产品技术设计，不要求在 MVP 一次实现；高级模块和对应数据表随阶段添加。每个发布阶段 Web 与小程序功能对等。

## 1. 目标与实现边界

交付面向销售及客户运营的 Web、小程序和共用服务端。用户管理多个微信发送账号和好友，利用模板、变量与 AI 创建消息，确认后立即或单次定时发送邮件。

执行单位是一位好友、一条最终文案、一封标签文本邮件。服务端内部 API 可以使用 JSON，邮件传输不要求快捷指令解析 JSON。手机端不再循环好友或等待间隔。

不设置固定的账号、好友总数及任务人数产品上限；后台分页、分批、串行投递，仍服从发信供应商速率及文件大小等工程边界。默认间隔为 10～15 秒，最小值为 10 秒。

首版只能确认发信服务是否接受邮件。用户当前设备实测动态联系人锁屏可能要求确认，无法承诺锁屏全自动运行。服务端邮件间隔不等于微信发送间隔，延迟邮件可能集中到达。

## 2. 技术架构与目录

以下是默认工程建议，落地时使用互相兼容的稳定版本并提交锁文件。

| 异步任务 | Redis、BullMQ、独立 Worker | 邮件、AI、导入及内容渲染 |

## 3. 页面与交互

| 模块 | Web | 小程序 |
| --- | --- | --- |
| 登录 | 账号密码，后续小程序扫码 | 账号密码过渡，后续微信登录及绑定 |
| 工作台 | 近期任务、配置入口、待处理提醒 | 今日任务、快捷创建 |
| 发送账号 | 列表、配置向导、邮箱验证、测试 | 配置指引、账号管理、测试 |
| 好友 | 列表、分组、批量粘贴、截图识别确认 | 同等核心能力，分步操作 |
| 内容 | 模板筛选、收藏、编辑、变量插入 | 浏览、收藏、创建编辑 |
| 变量 | 固定/随机/顺序列表，Excel/CSV 预览导入 | 同等核心能力及文件选择导入 |
| 任务 | 草稿、创建向导、立即/定时、取消、记录 | 同等核心能力，适配小屏 |
| AI 助手 | 文案、模板、自然语言任务草稿 | 同等核心能力 |
| 设置 | 时区、地区、微信身份绑定 | 同步设置、扫码登录确认 |
| 内容后台 | 管理员审核发布、平台变量维护 | 相同管理员权限下提供同等管理能力 |

首次使用：登录 → 添加账号和自己的邮箱 → 验证邮箱所有权 → 配置主题和 iPhone 自动化 → 添加测试好友备注 → 用户主动发送测试 → 在微信核对 → 用户标记测试结果。

邮箱验证邮件使用独立主题，避免触发自动化。界面区分“邮箱已验证”“测试邮件已发送”“用户确认测试成功”，不显示未经监测的设备在线状态。默认同一个有效邮箱只能绑定一个有效发送账号；跨用户冲突不透露占用者。

创建任务：编辑文案 → 多选发送账号 → 分别选择好友/分组 → 设置变量、地区、间隔 → 选择立即或定时 → 预览对象及内容 → 用户明确提交。每一步可保存草稿。

默认北京时间；定时是开始排队的目标时间，不是全体好友同时收到。执行中允许取消剩余未开始投递项，已发邮件无法撤回。已提交任务修改采用取消未投递部分、复制为草稿重新确认，避免改变已确认内容。

## 4. 业务规则

### 4.1 好友和导入

- 同账号唯一键为 `(owner_id, account_id, remark_key)`。备注保存原始显示值，键只做 Unicode NFC 和首尾空白清理，不删除内部空格、标点或 Emoji，不改拼音或大小写。
- 备注必须单行、非空，不包含协议保留标签。备注改变需要用户在微信与平台同步，平台无法自动更改或验证微信备注。
- 分组属于一个账号，好友可以进入多个分组，禁止跨账号关联。任务按账号与好友 ID 去重，不按全局姓名去重。
- 粘贴支持中英文逗号、分号、换行、制表符；备注包含分隔符时可切换为只按换行拆分。
- 截图由服务端多模态 AI 提取候选备注，标记不确定项；用户确认后导入。确认时再次检查唯一性，重复项跳过并报告，不覆盖已有好友。
- 好友停用后未投递项跳过；备注修改后未投递项进入待复核，不能悄悄发给新备注或继续使用旧备注。

### 4.2 模板与变量

| 变量 | 首版取值规则 |
| --- | --- |
| 日期、时间、星期 | 使用任务计划时间和时区，立即任务用提交时间；同任务好友一致 |
| 好友称呼 | 称呼非空时使用称呼，否则备注；微信收件人始终使用备注 |
| 天气 | 任务地区优先、账号默认地区其次；到期时查询，并缓存本次任务/地区结果 |
| 随机语录、问候 | 从平台审核列表按每位好友取一次 |
| 自定义固定 | 使用单个值 |
| 自定义随机 | 每位好友取一次，同条文案重复引用同变量得到同值 |
| 自定义顺序 | 按任务稳定收件人顺序循环，每个任务从第一项开始；首版不设跨任务全局游标 |

变量名称采用英文、数字和下划线，不覆盖内置名称，另有中文显示名。不重复随机和权重随机后续再做。

预览生成内容版本、随机种子和稳定的账号/好友排序。确认提交引用该预览版本；服务器核验范围及文案未变，冻结好友名单、备注/称呼、模板及变量候选值。分组新增成员、模板修改不影响已提交任务。

静态最终文本异步分批生成，与已确认预览保持一致。天气到期时再补齐，预览明确显示它可能变化。所有最终文本在发信前持久化，邮件重试不重新随机或重新取天气。天气有限重试仍失败则标记内容准备失败，不发送占位符，也不静默删去天气内容。

空内容、未知变量、空候选集、缺地区、无效间隔及时间都阻止提交。

### 4.3 Excel/CSV

支持 `.xlsx` 和 UTF-8 CSV。默认列：变量名称、显示名称、取值方式、候选内容；同变量多行组成候选列表。单变量编辑页可只导入一列候选值。

预览显示行号及错误；同变量模式冲突要求修正。只解析数据，不执行公式和宏；公式单元格要求转成值。技术性文件大小上限可配置，大文件分批导入，不限制变量总条数。导出文本做电子表格公式注入防护。

### 4.4 投递节奏

- 优先使用任务内该账号的间隔覆盖值，再用账号默认，最后用 10～15 秒。固定值即最小值等于最大值，任何配置都不得低于 10 秒。
- 仅接受正整数且 `10 ≤ minDelay ≤ maxDelay`。界面显示预计完成时间；很长任务提示排队影响。
- 同一账号的不同任务、测试邮件和重试共用串行槽；不同账号允许并行，同时服从供应商全局额度。
- 任务提交时按“该账号好友数 × 最大间隔”预留账号执行时间窗，每位好友都包含一次发送后的冷却间隔。例如 10 位好友、固定 10 秒间隔会占用 100 秒。新任务无论安排在已有任务之前还是之后，只要执行时间窗重叠都拒绝创建；恰好从已有时间窗结束时开始允许提交。
- 定时任务到期才进入 BullMQ 就绪队列，但时间窗会在创建时持久化预约。后端在账号行锁事务内完成最终冲突校验，前端检查只用于提前提示，不能代替服务端校验。
- 每次发信尝试结束后采样间隔，持久化 `next_allowed_at`；Worker 重启后从当前时间继续节奏，不突发补发积压。
- 明确失败项按自己的退避时间重试，不无限阻塞其他好友。每次尝试也计入服务商速率。
- 任务提交时保存账号配置版本。邮箱、主题或校验值变化、账号停用后，未投递项进入待复核；不静默改发新邮箱或继续投旧配置。
- 发信前再次校验配置版本、好友状态和取消标记。已进入外部调用的项可能在取消后成功，必须记录实际结果。

默认间隔是用户配置默认值，尚不能视作手机端可靠阈值。独立邮件减少同一次循环中断的影响，但手机邮件推送延迟和自动化并发仍需测试。

## 5. 队列、状态与恢复

### 5.1 调度设计

PostgreSQL 保存任务事实；BullMQ 用于执行和唤醒。任务提交在一个事务内写入任务、选择范围快照及 Outbox 事件。后台分批展开消息明细，记录游标，并使用 `(task_id, account_id, friend_id)` 唯一约束避免重复展开。

“全选分组/全部好友”由服务器生成持久化名单快照，不要求浏览器一次加载或提交所有记录。展开期间的数据库中断可以从游标恢复，不重新采样内容。

Worker 通过数据库原子抢占账号执行槽、明细和租约，多个进程不得并行投递同一账号。外部调用前保存 attempt_id 及 sending 状态。租约过期且外部结果未知时置为 unknown，不能把它当作普通失败自动重新调用。

Outbox 扫描及数据库状态可以恢复漏写队列的工作。BullMQ 官方建议任务保持简单并具备幂等性，见 [幂等任务文档](https://docs.bullmq.io/patterns/idempotent-jobs)。本方案将明细创建、内容准备和邮件发送分离；数据库幂等不能消除外部发信的不确定窗口。

### 5.2 状态模型

| 明细状态 | 页面文字 | 含义 |
| --- | --- | --- |
| pending / preparing | 待处理 / 内容准备中 | 等时间、展开、渲染 |
| ready | 待投递 | 等待账号槽和间隔 |
| sending | 邮件发送中 | 已开始外部发信调用 |
| accepted | 邮件已发送 | 发信服务明确接受；不代表邮箱或微信送达 |
| retry_wait | 等待重试 | 明确未接受的临时失败 |
| failed | 邮件发送失败 | 明确失败，重试已结束或不可重试 |
| content_failed | 内容准备失败 | 外部变量等无法准备 |
| unknown | 结果待核实 | 可能已发送，不能安全自动重发 |
| needs_review | 配置待复核 | 邮箱/主题/备注等改变 |
| cancelled / skipped | 已取消 / 已跳过 | 未投递且停止处理 |

退信单独保存 delivery_event，可显示“邮件退回”，保留之前被接受的历史。任务汇总各状态数量，完成可称“处理完成”，同时保留失败/未知数量，不用“微信已送达”或模糊的“全部发送成功”。

### 5.3 重试策略

明确未被服务接受的临时错误最多自动重试 3 次，指数退避并服从账号间隔；永久拒绝直接失败。提交后超时、连接中断、服务已接受但结果落库失败均进入 unknown，优先利用供应商请求 ID 查询，不能核实则保持未知。

只有供应商明确支持且幂等键仍有效时，才按其合约安全重试同一请求。SMTP Message-ID 相同不保证去重，BullMQ jobId 相同也不保证微信只发送一次。首版不承诺端到端恰好一次。

不因没有微信回执而重发；人工重发生成新的明细并显示可能重复，记录来源。手机端查找不到好友的错误，服务端首版不具备自动感知能力。

## 6. 数据模型

首版每位平台用户独立使用，所有业务表以 owner_id 隔离；每次读取、写入及关联均校验归属。团队角色暂不实现。

| 实体 | 关键字段与约束 |
| --- | --- |
| users | 登录名、密码哈希、时区、状态 |
| auth_identities | user_id、provider、AppID、OpenID；组合唯一 |
| sessions / login_tickets | 会话摘要、票据摘要、浏览器绑定、状态、有效期、消费时间 |
| wechat_accounts | owner_id、名称、邮箱、主题、地区、间隔、状态、config_version、校验值密文 |
| mailbox_verifications | 邮箱、验证凭证摘要、到期和消费时间 |
| friends | owner/account、remark、remark_key、称呼、版本、状态；账号内备注唯一 |
| groups / friend_groups | 所属账号、分组名称、好友关联；禁止跨账号 |
| tags / friend_tags | 所属用户、标签及好友关联 |
| templates / template_versions | 所属用户或平台、正文、行业场景、变量声明、版本、审核状态 |
| favorites | user_id/template_id 唯一 |
| variables / variable_items | 所属用户、唯一名称、模式、候选值、排序、版本 |
| tasks | 所属用户、标题、计划时间、时区、状态、预览版本、种子、提交幂等键 |
| task_account_settings | task/account 唯一、配置快照、间隔 |
| task_recipients | 冻结的好友范围、顺序、备注和称呼 |
| task_messages | task/account/friend 唯一、message_id、最终文案、状态、ready_at |
| delivery_attempts / delivery_events | 消息、供应商请求 ID、错误分类、时间、接受或未知结果、退信 |
| account_dispatch_state | account_id 唯一、next_allowed_at、租约、当前 attempt_id |
| outbox_events | 事件、处理状态、恢复时间、展开游标 |
| import_jobs / import_candidates | 来源、解析状态、候选行、错误、确认状态 |
| ai_jobs | 所属用户、任务类型、模型、结果、耗时及消耗 |
| assets | 所属用户、私有路径、用途、到期和删除状态 |
| audit_logs / notifications | 关键操作、脱敏错误、站内通知 |

重点索引为 `(account_id, state, ready_at)`、`(owner_id, created_at, id)`。删除账号或好友优先归档，不级联删除发送历史。

## 7. API 初稿

统一 `/api/v1`，游标分页，稳定错误码；具体请求/响应 schema 在 P0/P1 实现前补齐 OpenAPI。

| 模块 | 主要接口 |
| --- | --- |
| 登录 | `POST /auth/login`、`POST /auth/logout`、`GET /me` |
| 账号 | `GET/POST /accounts`、`PATCH /accounts/:id`、`POST /accounts/:id/test` |
| 验证邮箱 | `POST /accounts/:id/verification`、`POST /accounts/:id/verification/confirm` |
| 好友分组 | `GET/POST /accounts/:id/friends`、`PATCH /friends/:id`、`GET/POST /accounts/:id/groups` |
| 导入 | `POST /imports`、`GET /imports/:id`、`POST /imports/:id/confirm` |
| 模板变量 | `GET/POST /templates`、`GET/POST /variables`、`POST /templates/:id/preview` |
| 任务 | `POST /tasks`、`POST /tasks/:id/preview`、`POST /tasks/:id/submit`、`POST /tasks/:id/cancel` |
| 记录 | `GET /tasks`、`GET /tasks/:id/messages`、`GET /messages/:id/attempts` |
| AI | `POST /ai/copy-jobs`、`POST /ai/task-draft-jobs`、`GET /ai/jobs/:id` |
| 扫码扩展 | 创建票据、读取状态、小程序确认、浏览器兑换四个独立接口 |
| 管理后台 | 模板审核发布、平台变量维护、供应商配置状态 |

提交、导入确认、测试发信要求幂等键。草稿接口无发送副作用。供应商密钥不通过任何客户端接口返回。

## 8. 登录演进

MVP 使用账号密码登录，内测账号由受控部署管理命令创建，公开注册和找回密码入口放在 P5。Web 默认 HttpOnly Cookie 会话并配套 CSRF 校验；小程序使用可过期、可撤销的应用会话。

小程序微信身份与平台账号绑定时验证已有账号，避免生成两份数据。身份以 AppID 下 OpenID 为基础，不假设必有 UnionID。

Web 扫码规划：浏览器申请短期随机票据 → 展示进入小程序确认页的码 → 小程序登录并展示本次网页登录 → 用户确认 → 原浏览器验证绑定后兑换一次性结果 → 建立会话。

二维码不携带长期令牌；票据过期、拒绝或消费后不能再次登录。状态轮询不返回登录凭证，兑换接口检查浏览器绑定。小程序登录不等于批准某个浏览器登录。

微信官方小程序文档本次抓取失败，此处为设计流程；wx.login、登录凭证交换、小程序码 scene 及页面路径约束，在 P4 用真实 AppID 核验后实现，不按未核验的参数上限编码。

## 9. AI 和内容运营

图片选择 → 上传私有存储 → 多模态模型提取结构化候选 → 服务端校验 → 用户纠正/确认 → 幂等导入。图片内文字仅为待识别数据，模型不能调用发信、删除或账号修改接口，不能臆造模糊姓名。

原图和导入文件默认在确认后尽快删除，最长不超过创建后 24 小时；未确认及失败文件同样清理。保留期限为工程默认。结构化好友数据按正常业务保留；供应商请求和日志不公开好友列表。

AI 文案输入行业、场景、语气、产品事实及可用变量，输出候选。未知变量、价格、活动期限要求用户补充。AI 任务草稿返回账号/分组、时间、文案、缺失项，名称只能映射为当前用户拥有的记录；歧义保持待完善。任何模型输出都不能直接提交邮件。

首批内容建设目标 120 条：通用销售、零售门店、家居建材、汽车销售/售后各 30 条；每组活动通知、节日问候、降价提醒各 10 条。该选行业建议源于用户场景，尚未进行市场调研，不作为市场规模结论。

AI 初稿 → 编辑审核 → 校验变量和协议保留字 → 示例预览 → 发布。记录行业、对象、语气、版本及编辑记录；使用次数不冒充营销转化率。本次未生成这 120 条内容。

## 10. 部署与运行

开发使用本地数据库、Redis、邮件沙箱及模拟 AI/天气；真实联调使用指定测试账号。Web、API、Worker 独立部署，数据库迁移纳入发布，备份和恢复写入运行手册。

记录队列积压、最旧等待时间、服务商拒绝率、unknown 数量、AI 耗时成本和临时文件清理结果。不从邮件成功推断设备在线。发信身份和额度属于平台配置，接收邮箱不要求用户提供密码。

需实现用户数据隔离、会话安全、私有文件访问、导入校验、敏感配置脱敏。产品不设总数量上限，仍使用分页、批处理、供应商限流和成本统计。
