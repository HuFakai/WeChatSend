# WeChatSend 项目介绍

> 文档状态：功能确认版 v1.2，已选黑白极简，按 MVP 分阶段交付
> 更新日期：2026-09-07
> 配套文档：[分阶段开发计划](./分阶段开发计划.md)、[项目开发方案](./项目开发方案.md)、[标签邮件协议与快捷指令](./标签邮件协议与快捷指令.md)

## 1. 项目概述

WeChatSend 是一个面向销售与客户运营人员的 SaaS，提供功能完整一致的 Web 和微信小程序两个入口，集中管理微信文本消息任务。小程序仅调整移动端布局，不删减功能；同一角色在两端具有相同管理能力。Web 使用 React + shadcn/ui。

平台本身不直接登录或控制用户的微信账号，而是将待发送的联系人和文本内容编码为约定格式的邮件，发送到用户指定的邮箱。用户 iPhone 上的邮件自动化接收邮件并运行快捷指令，再由快捷指令调用微信的“发送信息”能力完成消息发送。

项目希望解决以下问题：

- 将分散在快捷指令中的联系人、文案和定时任务集中管理。
- 支持一个用户管理多个微信账号及各账号下的好友和分组。
- 通过模板、变量、行业话术和 AI 降低文案制作成本。
- 支持立即发送、定时发送，并保留任务和邮件投递记录。

当前已验证的核心链路是：

```text
Web / 微信小程序
        ↓
创建消息任务
        ↓
服务端生成并发送邮件
        ↓
iPhone 邮件自动化触发快捷指令
        ↓
快捷指令解析联系人和消息正文
        ↓
调用微信发送文本消息
```

## 2. 当前产品边界

### 2.1 已明确的能力

- 通过邮件触发 iPhone 快捷指令。
- 从邮件正文中提取微信好友备注和消息内容。
- 调用微信快捷指令动作发送文本消息。
- 后续可由一个平台账号管理多个“微信发送账号”。

### 2.2 当前限制

- 当前微信快捷指令动作按“文本消息”设计，首版不支持直接发送图片、视频或普通文件。
- 微信账号必须已经登录在配置好的 iPhone 上。
- iPhone 需要保持邮件可正常接收，相关自动化、快捷指令权限和微信权限需要由用户完成配置。
- 平台能够确认任务处理结果、邮件发送结果，以及快捷指令是否报告微信发送动作成功；仍无法获得微信官方送达或已读回执。
- 好友备注被修改、好友不存在、手机离线、系统权限变化或微信/iOS 更新，都可能导致终端执行失败。
- 用户实测动态联系人在锁屏状态可能需要确认；首版不能承诺锁屏全自动发送，使用条件按实际设备测试记录说明。
- 用户实测联系人不存在会中断本次快捷指令，所以最终确定一位好友一封邮件。后续独立邮件的设备执行仍需联调验证。
- 服务端控制的是邮件投递间隔，不能保证邮件到达顺序、微信发送顺序或实际微信发送间隔。
- 平台不得用于骚扰、垃圾营销、欺诈或其他违反法律法规及微信平台规则的行为。

## 3. 核心概念

### 3.1 平台用户

使用 Web 端或微信小程序管理微信发送账号、好友、模板和任务的人。

### 3.2 微信发送账号

一个已经配置好邮件自动化和快捷指令的 iPhone/微信运行环境。已确定一个微信账号固定对应一台 iPhone 和一个用户自己的接收邮箱。平台使用自己的发信服务投递，不要求用户提供接收邮箱密码。

每个微信发送账号至少包含：

- 账号名称，例如“客服微信 1”“个人微信”。
- 接收邮件地址。
- 邮件主题匹配规则，选填。
- 可选安全校验信息，例如专属口令或签名密钥。
- 设备备注和配置状态。
- 最近一次测试时间和测试结果。

### 3.3 微信好友

隶属于某个微信发送账号，以微信中的好友备注作为快捷指令的收件人标识。

### 3.4 消息模板

由固定文本和变量组成，可以是平台模板、行业模板或用户自建模板。

### 3.5 变量

任务执行时才转换为具体文本的数据占位符，例如 `{{date}}`、`{{weather}}`。

### 3.6 发送任务

指定发送时间、微信发送账号、好友范围和消息内容的一次任务。一个面向多个账号或好友的任务，在执行时会拆分为多条独立发送记录。

## 4. 功能模块

### 4.1 用户与账号体系

- Web 端注册、登录和退出。
- 开发初期 Web 和小程序使用账号密码，共用平台用户身份；后续接入小程序登录及 Web 小程序扫码确认登录。
- 用户资料和基础设置。
- 不同端登录后的数据同步。
- 后续可扩展套餐、额度、团队成员和权限管理。

### 4.2 微信发送账号管理

- 新增、编辑、停用和删除微信发送账号。
- 填写接收邮件地址。
- 设置邮件主题；不填写时使用平台默认主题。
- 提供快捷指令安装和配置教程。
- 发送测试消息，帮助用户检查邮箱、自动化、快捷指令和微信配置。
- 显示配置状态、最近测试邮件结果、用户确认的测试结果和最近任务时间；没有设备心跳时不显示“设备在线”。

建议在正式使用前强制完成一次测试发送。

### 4.3 好友管理

#### 手动添加

- 填写好友备注。
- 选择所属微信发送账号。
- 设置分组、标签和备注信息。
- 同一发送账号内微信好友备注唯一，Web、小程序及服务端执行相同校验；不同账号允许同名。用户需在微信中同步修改重名备注。

#### 批量粘贴

支持自动识别以下分隔方式：

- 中文逗号 `，`
- 英文逗号 `,`
- 中文或英文分号 `；`、`;`
- 换行
- 制表符

系统应自动执行去除首尾空格、过滤空值和重复项检查，并在保存前展示整理结果。

#### 截图识别

- 上传微信通讯录或好友列表截图。
- 服务端调用多模态 AI 直接识别并整理候选好友备注。
- 自动清除界面按钮、字母索引等非联系人文本。
- 对疑似重复项和识别不确定的结果作出标记，不把模型自报置信度当成准确率。
- 必须经过用户确认和修改后才能导入好友列表。
- 原始截图的保存期限和删除机制需要明确，避免不必要地保留联系人隐私数据。

#### 好友分组与标签

- 一个好友可以进入多个分组。
- 支持批量移动、批量打标签和批量停用。
- 创建任务时可以按分组、标签或好友名称筛选。

### 4.4 内容与模板中心

消息内容支持以下来源：

- 用户直接输入。
- 从剪贴板粘贴。
- 选择平台公共模板。
- 选择行业话术模板。
- 选择用户自建模板。
- 由 AI 生成或改写。

模板应支持复制、编辑、收藏、分类、预览和另存为用户模板。

平台公共内容建议按以下维度组织：

- 行业。
- 使用场景。
- 沟通对象。
- 文案语气。
- 节日或时间节点。
- 消息目的，例如问候、提醒、回访、通知、邀约、维护关系。

### 4.5 变量系统

#### 平台变量

第一阶段可以提供：

- `{{date}}`：当前日期。
- `{{time}}`：当前时间。
- `{{weekday}}`：星期。
- `{{weather}}`：指定地区天气。
- `{{random_quote}}`：随机语录。
- `{{random_greeting}}`：随机温馨问候。
- `{{friend_name}}`：好友名称或用户为好友配置的称呼。

天气地区首版采用任务指定地区优先、微信发送账号默认地区其次；好友级地区作为后续扩展。

#### 用户自定义变量

用户可以创建一个变量并录入多条候选值，例如：

```text
变量名称：product_name
候选值：产品 A、产品 B、产品 C
```

建议支持以下取值方式：

- 固定值。
- 随机取值。
- 按顺序循环取值。
- 支持 Excel（.xlsx）/CSV 导入候选值，并在保存前预览校验。
- 不重复随机，全部使用后重新开始，作为后续扩展。
- 后续扩展带权重随机。

模板示例：

```text
{{friend_name}}，{{random_greeting}}
今天是 {{date}}，{{weather}}。
想向你介绍一下 {{product_name}}。
```

创建任务前必须提供“实际内容预览”，让用户看到变量替换后的最终文本。对于多位好友，可以抽样预览或逐条查看。提交后冻结好友范围、模板和变量候选值；随机结果可复现，重试不重新取值。定时任务天气在到期时获取，预览明确提示这一动态字段会变化。顺序变量首版按每个任务的固定好友顺序循环，不建立跨任务全局游标。

### 4.6 消息发送任务

创建任务建议分为四步：

1. 编辑或选择消息内容。
2. 多选微信发送账号。
3. 分别选择每个账号下的好友、分组或标签。
4. 选择立即发送或定时发送，并确认任务。

建议支持：

- 立即发送。
- 指定日期和时间发送。
- 保存为草稿。
- 发送前预览最终文本和接收对象数量。
- 对重复选择的好友自动去重。
- 服务端设置邮件之间的投递间隔，固定值或随机范围，默认 10～15 秒且最小 10 秒。同一账号跨任务串行，任务配置可覆盖账号默认值。
- 任务开始前取消。
- 仅对明确未被发信服务接受的临时失败有限重试；结果不确定时不自动重发。
- 后续根据需求增加每日、每周、每月等周期任务。

任务执行时，服务端按“微信发送账号 + 好友”拆分为独立发送记录。最终确定一封邮件只包含一个联系人和一条文本消息，快捷指令不再循环或等待。不设置固定的账号数、好友数或单任务人数产品上限，后台采用分页、分批及队列处理，仍服从请求大小及服务商速率等工程限制。

建议的任务状态：

- 草稿。
- 等待执行。
- 执行中。
- 邮件已发送。
- 邮件发送失败。
- 结果待核实（邮件可能已发送，不能安全自动重试）。
- 已取消。

在没有手机端回执机制之前，不能把“邮件已发送”显示成“微信已送达”。

### 4.7 AI 能力

#### AI 文案助手

- 根据行业、场景、对象、目的和语气生成文案。
- 扩写、缩写、润色、纠错和改变语气。
- 将普通文案转换为带变量的模板。
- 一次生成多个候选版本供用户选择。

#### AI 创建任务

用户可以使用自然语言描述任务，例如：

```text
明天上午 9 点，用客服微信给“老客户”分组发送一条中秋问候，语气自然，不要太营销。
```

AI 将描述转换成任务草稿，包括发送时间、账号、好友范围、模板和变量。涉及真实发送时，必须先展示结构化结果并由用户明确确认，不能仅凭一次自然语言输入直接对外发送。

#### AI 辅助好友整理

- 使用多模态 AI 识别截图并整理候选好友。
- 识别可能的姓名和备注。
- 合并疑似重复项。
- 推荐好友分组，但由用户确认后保存。

### 4.8 行业话术库

行业话术是平台长期内容资产，首批以通用销售、零售门店、家居建材、汽车销售/售后为方向，围绕产品活动通知、节日问候、降价提醒。AI 生成初稿与平台编辑审核结合。这是基于产品场景的设计建议，尚未经过市场调研验证。

每条行业内容建议包含：

- 标题和正文。
- 行业、场景和标签。
- 推荐语气和适用对象。
- 可使用的变量。
- 示例预览。
- 内容版本和审核状态。
- 使用次数、收藏次数和用户反馈。

平台需建立内容审核、版权来源和敏感词检查机制，避免提供虚假宣传、骚扰营销或高风险行业违规话术。

### 4.9 任务记录与通知

- 查看任务列表和任务详情。
- 查看每个账号、好友对应的邮件发送记录。
- 展示失败原因和重试记录。
- 任务完成或失败后发送站内通知。
- 后续可增加小程序订阅消息。
- 支持按时间、账号、好友和任务状态筛选。

## 5. 已确定的邮件协议

回归已经跑通的标签文本，不要求快捷指令解析 JSON。每位好友一封 UTF-8 纯文本邮件：

```text
[USER]
微信好友备注
[/USER]

[MESSAGE]
最终渲染后的文本消息
[/MESSAGE]
```

平台邮件增加协议版本、任务编号和独立消息编号：

```text
[VERSION]
1
[/VERSION]

[TASK_ID]
平台任务编号
[/TASK_ID]

[MESSAGE_ID]
平台消息明细编号
[/MESSAGE_ID]

[USER]
微信好友备注
[/USER]

[MESSAGE]
最终渲染后的文本消息
[/MESSAGE]
```

可选 TOKEN 校验必须与手机端校验动作一起实现并验证；固定 TOKEN 是持有者口令，不是签名，不防重放。字段 ID 用于追踪，本身不保证手机端去重。邮件中不再携带发送间隔。详细边界、保留标签及提取步骤见配套协议文档。

## 6. 首版交付范围

首版改为可独立内测的 v0.1 MVP，目标是先跑通平台到真实 iPhone 微信的完整链路。所有阶段 Web 和小程序功能对等，不等待高级模块全部开发完再交付。

1. 内测账号密码登录和退出（管理命令创建账号，公开注册后续交付）。
2. 微信发送账号管理及测试发送。
3. 好友手动添加、编辑、批量粘贴、搜索多选、备注唯一及停用。
4. 手工输入或粘贴文本；多账号、各账号多好友选择。
5. 收件人和内容预览、立即发送和单次定时、固定或范围间隔。
6. 一好友一封标签邮件、同账号跨任务串行、取消未投递项。
7. 明确失败有限重试、未知结果管理、邮件发送记录及错误原因。
8. 用户隔离、输入校验、部署说明、双端和真实设备联调。

后续按版本增加已确认功能：

- v0.2：好友分组/标签、模板/收藏、基础变量和手工自定义列表、任务草稿和复制。
- v0.3：多模态 AI 截图导入、Excel/CSV 变量导入、天气及随机语录/问候。
- v0.4：AI 文案/模板/任务草稿、内容后台、首批 120 条行业/通用模板目标。
- v1.0：小程序微信身份绑定、微信个人主体虚拟支付、Web 支付宝订单码支付、会员套餐与通用权益、Web 小程序扫码、公开注册/找回密码、通知和设置完善。

周期任务、团队协作、微信送达回执及图片文件发送不自动进入上述阶段。完整产品功能说明不等于 MVP 全部实现范围，阶段边界以《分阶段开发计划》为准。

## 7. 功能决策记录

| 原问题 | 2026-09-07 确认结果 |
| --- | --- |
| 首批用户与场景 | 销售/客户运营；活动通知、节日问候、降价提醒；优先零售、家居建材、汽车销售 |
| 接收邮箱来源 | 用户填写自己的邮箱 |
| 设备对应关系 | 一个微信账号固定对应一台 iPhone 和一个接收邮箱 |
| 好友匹配 | 微信备注；同一账号唯一；提醒用户在微信修改重名备注 |
| 首版周期任务 | 不做；只做立即和单次定时 |
| 数量与间隔 | 不设账号/好友总数量产品上限；服务端投递间隔可配置 |
| 发送结果 | 接受只报告邮件结果，不能确认微信送达 |
| 截图识别 | 服务端多模态 AI，用户确认后导入 |
| 变量导入 | 支持 Excel/CSV |
| AI 创建任务 | 仅生成草稿，用户确认才提交 |
| 行业内容 | AI 初稿与平台编辑结合；首批行业采用上述建议 |
| 产品与登录 | 营销/客户运营 SaaS；Web 前后端分离及小程序；先账号密码，后小程序扫码 |

“没有账号和好友现在”按上下文解释为“不限制账号和好友数量”。默认每位平台用户独立管理数据，团队和付费套餐另行扩展。

## 8. 当前下一步

用户已选择 A 黑白极简。接下来先设计并确认 MVP 双端页面及关键状态，再开发 MVP；后续模块按阶段补设计和实现，不要求先画完所有远期页面。真实邮件与小程序环境在 MVP 联调前配置，AI/天气等依赖随所属阶段配置。阶段目标及验收见《分阶段开发计划》，技术细节见《项目开发方案》。
