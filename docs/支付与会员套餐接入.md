# 支付与会员套餐接入

当前版本提供两条支付链路，订单和会员权益都由服务端落库：

- Web：支付宝订单码支付，服务端调用 `alipay.trade.precreate` 生成二维码，浏览器轮询订单并接收支付宝异步通知。
- 微信小程序：个人主体虚拟支付，道具直购模式 `short_series_goods`，服务端生成 `paySig`/`signature`，以发货推送为主、`query_order` 查单为兜底。

两种渠道最终都写入 `membership_grants`，同一个订单只能发放一次权益。管理员开启 `membership_required` 后，创建发送任务会在数据库事务中校验有效权益并预扣消息额度；取消尚未发送的消息会退回额度。支付成功只代表平台确认并发放套餐，不代表微信消息已经送达。

## 微信小程序虚拟支付

开通前确认小程序是个人主体、服务类目包含“工具”、已完成认证和备案，并在微信公众平台完成虚拟支付审核。个人主体全终端月支付限额为 10 万元；iOS 还需要配置小程序简称并使用满足要求的微信版本。

服务端配置步骤：

1. 微信后台“支付与交易 → 虚拟支付”获取 AppID、OfferID、现网 AppKey。
2. 在“道具管理”创建并发布商品，保存 ProductID。
3. 进入 Web 管理员页面“平台配置 → 支付与套餐”，填写 OfferID、AppKey、推送 Token 和推送模式。
4. 把 `https://你的域名/api/v1/virtual-payment/notify` 配置到微信发货推送地址，官方推送格式选择 XML。
5. 创建套餐时，`ProductID` 必须与微信后台商品一致，价格单位填写分。

支付签名和发货逻辑已经写入 `web/backend/src/virtual-payment.ts`：

- 下单的 `signData` 使用实际发送给 `wx.requestVirtualPayment` 的原始 JSON 字符串；`paySig` 的签名原文是 `requestVirtualPayment&signData`。
- `query_order` 的 `pay_sig` 签名原文是 `/xpay/query_order&post_body`。
- 发货以微信推送中的 `WeChatPayInfo.MchOrderNo` 作为 `wx_order_id` 记录，并使用 `(source, source_order_id)` 唯一约束幂等发放。
- AppKey、EncodingAESKey 和小程序 `session_key` 只在服务端加密字段中保存，不进入小程序包和日志。
- 管理员页面不会回显 AppKey、推送 Token 和 EncodingAESKey；修改其他配置时密钥留空即可沿用已有值。
- 管理员页面会检查已保存的 AppKey/EncodingAESKey 能否被当前 `APP_ENCRYPTION_KEY` 解密。线上更换该环境变量后，旧密文无法恢复，需要重新填写对应密钥并保存；正常更新部署时不要随意更换它。
- 所有推送模式都验证 URL 签名；安全模式还校验 32 字节填充和接收 AppID。发货前主动调用 `query_order` 复核，不能仅凭客户端回调或推送正文发放权益。
- iOS 检查微信 8.0.68 最低版本；取消、断网或退出后可从“小程序 → 我的 → 订单记录”恢复查单或继续支付。

小程序打开 `pages/pay/index` 且没有扫码场景时会展示套餐；从旧的微信支付二维码进入时仍保留原生微信支付流程。

### “数据不存在”排查

如果 `wx.requestVirtualPayment` 返回“数据不存在”并附带 `rid`，说明请求已经到达微信，但微信没有在当前支付配置下找到匹配的现网支付数据。依次检查：

1. 小程序工程 AppID、服务端 `WECHAT_MINI_APPID` 和支付配置 AppID 完全一致。
2. OfferID 和现网 AppKey 来自同一个已开通虚拟支付的现网账号；不要填写沙箱 AppKey。
3. 套餐 ProductID 与当前 OfferID 下“道具管理”中已发布道具的 ID 完全一致，包括大小写。
4. 套餐价格单位为分，并与微信后台道具价格一致；例如页面显示 `¥19.90` 时应填写 `1990`。
5. 道具、小程序虚拟支付能力和对应版本均已完成审核/发布。修改后台道具后等待配置生效，再重新生成新订单测试。

当前项目会保留微信返回的 `rid` 并追加上述提示，便于在微信后台或技术支持中定位。`EncodingAESKey` 只用于兼容/安全模式的推送解密；明文模式可以留空，它不参与 `wx.requestVirtualPayment` 下单签名。

官方资料：[个人主体虚拟支付](https://developers.weixin.qq.com/miniprogram/dev/platform-capabilities/business-capabilities/virtual-payment/person.html)、[requestVirtualPayment](https://developers.weixin.qq.com/miniprogram/dev/api/payment/wx.requestVirtualPayment.html)、[query_order](https://developers.weixin.qq.com/miniprogram/dev/server/API/VirtualPayment/api_query_order.html)。

## Web 端支付宝订单码支付

服务端通过 `alipay-sdk` 调用 `alipay.trade.precreate`，使用订单码产品码 `QR_CODE_OFFLINE` 生成二维码。支付宝异步通知经过 SDK 验签，并校验订单号、AppID、交易号和订单金额后才发放权益；如服务端兼容配置中已有收款 PID，还会额外校验 `seller_id`。只有 `TRADE_SUCCESS` 或 `TRADE_FINISHED` 视为支付成功。过期订单先查单，仅在支付宝明确返回待付款时调用 `alipay.trade.close`；网络异常保持“待核实”。

支付宝参数优先在 Web 管理员“支付与套餐”页面维护，私钥加密入库且不会回显；环境变量继续作为首次部署兼容配置：

```dotenv
ALIPAY_APP_ID=""
ALIPAY_PRIVATE_KEY=""
ALIPAY_PUBLIC_KEY=""
ALIPAY_NOTIFY_URL="https://你的域名/api/v1/alipay/notify"
ALIPAY_ORDER_EXPIRE_MINUTES=30
```

后台只需填写 AppID、Node.js 使用的 PKCS#1 应用私钥原值、支付宝公钥和 HTTPS 通知地址。生产网关、RSA2 和 PKCS#1 由服务端固定，不作为管理页参数。私钥、公钥和测试账号不得放进 Git、截图、前端或日志。

关键接口：

| 接口 | 作用 |
| --- | --- |
| `GET /api/v1/alipay/plans` | 获取已上架套餐 |
| `POST /api/v1/alipay/orders` | 创建当前用户的订单码订单 |
| `GET /api/v1/alipay/orders/:id` | 查询本地订单 |
| `POST /api/v1/alipay/orders/:id/query` | 调用支付宝交易查询并按结果发放权益 |
| `POST /api/v1/alipay/notify` | 接收并验签支付宝异步通知 |
| `GET /api/v1/orders` | 当前用户分页查看支付宝/微信订单 |
| `POST /api/v1/orders/:channel/:id/query` | 当前用户主动向支付平台查单 |
| `GET /api/v1/admin/orders` | 管理员分页查看全部订单 |

订单码使用的是服务端返回的二维码图片，不把应用私钥交给浏览器。正式上线前必须配置公网 HTTPS 通知地址，并在沙箱完成“下单 → 扫码 → 支付 → 异步通知/主动查询 → 会员权益”的全链路测试。

Node SDK 参考：[支付宝官方 Node.js SDK](https://github.com/alipay/alipay-sdk-nodejs-all)。

## 数据库升级与部署

本次身份与支付闭环新增迁移：

- `20260908100000_virtual_payment`：小程序虚拟支付配置、商品套餐、虚拟支付订单和原始权益表。
- `20260908110000_alipay_and_membership_grants`：支付宝订单，并将旧权益迁移到通用 `membership_grants`。
- `20260908160000_identity_and_payment`：邮箱身份、一次性登录挑战、加密支付宝配置、订单快照和会员额度流水。

上线前先备份 PostgreSQL，然后执行：

```bash
docker compose -f web/deploy/docker-compose.prod.yml --env-file .env build
docker compose -f web/deploy/docker-compose.prod.yml --env-file .env --profile tools run --rm migrate
docker compose -f web/deploy/docker-compose.prod.yml --env-file .env up -d --remove-orphans
```

PostgreSQL 和 Redis 继续使用 1Panel 中已有的服务，不要执行 `down -v`，也不要在本项目 Compose 中重新创建 Redis。详细网络、Redis 容器名和更新命令见 [1Panel + Docker 线上部署](./1Panel-Docker线上部署.md)。
