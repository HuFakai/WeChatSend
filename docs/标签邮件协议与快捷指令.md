# 标签邮件协议与快捷指令

> 标签协议 v1 · 2026-09-07
> 范围：单好友文本；服务端逐封排队。快捷指令仍需在用户设备验证。

## 1. 邮件格式

一封邮件仅包含一个好友和一条消息，采用 UTF-8 `text/plain` 正文。不附加 HTML、Markdown 代码围栏、自动签名或转发历史。主题单独填写，默认 `WeChatSend`，可继续使用已配置的 `WeChat`。

最小兼容格式：

```text
[USER]
凯旋
[/USER]

[MESSAGE]
你好，这是单好友测试消息。
这条消息支持多行内容。
[/MESSAGE]
```

正式平台邮件增加追踪字段。TASK_ID 是每封邮件唯一的反馈 ID，
BATCH_ID 是整批发送任务 ID；MESSAGE_ID 在当前版本与 TASK_ID 相同，用于兼容：

```text
[VERSION]1
[TASK_ID]8d1ae78a-95aa-4458-ab82-f3eb085e3547
[BATCH_ID]63e6d655-1d18-45e7-ae45-d06ac23b1bf8
[MESSAGE_ID]8d1ae78a-95aa-4458-ab82-f3eb085e3547

[USER]
凯旋
[/USER]

[MESSAGE]
你好，这是单好友测试消息。
这条消息支持多行内容。
[/MESSAGE]
```

旧快捷指令只匹配 USER/MESSAGE 时可忽略元数据。TASK_ID 标识一条好友消息，
有限重试不更换该 ID；它同时作为不可预测的回调凭证，不要公开。邮件内不再传间隔。

如启用 TOKEN 模式，可增加 `[TOKEN]...[/TOKEN]`，同时在手机端添加相等校验。仅增加字段没有校验效果；固定 TOKEN 为持有者口令，不是签名，不防重放。

## 2. 字段边界

- USER 必须恰好一处、非空且单行，与微信备注一致。
- MESSAGE 必须恰好一处、非纯空白；保留内部段落和空格。
- USER/MESSAGE 的起止标签独占一行，元数据每项独占一行，均使用英文半角符号。
- 协议中所有完整起止标签都是保留字面量，备注和消息中不能出现。平台在提交前提示冲突，不擅自删除用户文字。
- 快捷指令验证 USER/MESSAGE 每个开始、结束标签各一次。只取第一个匹配而不计数可能忽略重复或转发内容。
- 引号、普通大括号、逗号、Emoji 可直接写入消息，不需要 JSON 字符串转义。

## 3. 快捷指令步骤

1. 从快捷指令输入获取文本，保存“邮件内容”；没有值则停止。
2. 使用“替换文本”，开启正则，把 `\r\n?` 替换为实际换行，保存“规范邮件内容”。替换框放真正的换行，不是字面量 `\n`。
3. 校验 USER/MESSAGE 起止标签各恰好一次，异常停止。
4. 在“规范邮件内容”中匹配用户名，取得组 1、修剪首尾空白，保存“用户名称”。
5. 再从“规范邮件内容”匹配消息，取得组 1，保存“消息内容”。
6. 检查用户名非空且无换行，消息非纯空白；可用消息副本做空白检查，发送保留原内容。
7. 如启用 TOKEN，匹配并校验，缺失或不一致停止。
8. 用用户名生成 vCard，改名 `m.vcf`，从文件获取联系人，保存“当前联系人”。
9. 微信将“消息内容”发送给“当前联系人”。
10. 仅当上一步没有报错时，匹配 TASK_ID 并调用反馈接口。反馈失败不能再次执行微信发送动作，只能单独重试反馈请求。

不添加好友循环、随机数和等待。测试时在发送前显示结果，正式自动化删除快速查看、显示结果等需要交互的调试动作。

用户名正则（规范换行后）：

```regex
(?m)^\[USER\][ \t]*\n([^\n]*)\n\[/USER\][ \t]*$
```

消息正则：

```regex
(?ms)^\[MESSAGE\][ \t]*\n(.*?)\n\[/MESSAGE\][ \t]*$
```

TASK_ID 正则：

```regex
(?m)^\[TASK_ID\]([0-9a-fA-F-]{36})[ \t]*$
```

每段都是“匹配文本 → 获取匹配文本的组（索引 1）”。返回匹配列表时先确认只有一项，再取该匹配的组 1。两个匹配的输入均显式选择“规范邮件内容”，组操作分别引用对应匹配，避免同名变量连错。

消息表达式只剥除协议边界的换行，不再无条件修剪消息首尾。如先兼容原已跑通的 `(?s)\[MESSAGE\]\s*(.*?)\s*\[/MESSAGE\]`，需接受它会去掉首尾空白的差异。

vCard 保持已验证的姓名字段布局：

```text
BEGIN:VCARD
VERSION:3.0
FN:【vCard转义后的用户名称】
N:【vCard转义后的用户名称】;;;;
END:VCARD
```

说明位置插入实际变量。为处理备注特殊字符，对用户名副本依次进行普通文本替换：`\` → `\\`，`;` → `\;`，`,` → `\,`，再用于 vCard。中文、Emoji、逗号、分号及反斜杠备注需在设备验收，不能擅自删除这些字符。

“用户名称”为文本，“当前联系人”为获取联系人动作输出。合成联系人存在不代表微信好友存在，查找失败仍会使本次运行中断。

## 4. 微信发送结果反馈

线上接口：

```text
POST https://你的域名/api/v1/feedback
Content-Type: application/json
```

成功反馈正文：

```json
{
  "task_id": "从邮件匹配到的 TASK_ID",
  "status": "success"
}
```

在“微信发送消息”动作后添加：

1. 在“规范邮件内容”中用 TASK_ID 正则匹配文本。
2. 获取匹配文本的组 1，保存变量“反馈任务ID”。
3. 添加“词典”，键 task_id 的值选择“反馈任务ID”，键 status 填写 success。
4. 添加“获取 URL 内容”，URL 填写完整 HTTPS 反馈地址，方法选择 POST，请求正文选择 JSON，并传入该词典。
5. 不要开启“运行时显示”；可将返回结果留作调试，正式运行时删除“快速查看”。

接口返回 ok: true 即表示平台已记录。重复调用同一个 TASK_ID 是安全的，返回
duplicate: true 时不会覆盖第一次反馈。failed 状态可附加 error 字段。当前反馈表示
“手机上的微信发送动作已执行且未报错”，不是微信官方的送达、已读回执。

## 5. 自动化与诊断

在收到符合主题/发件人条件的邮件后，运行目标快捷指令并显式传入触发邮件或已获取的邮件文本。按实际 iOS 界面选择输入，不依赖不存在的独立“获取邮件正文”动作。标签可在包含主题的文本中提取，无需删除固定主题字样。

逐步检查：原始邮件内容 → 用户匹配和组 1 → 消息匹配和组 1 → 联系人。快速查看无项目只说明它当时没有收到可预览项目，不能据此断定邮件原始输入为空。

手动测试可在顶部临时添加最小样例“文本”，把解析输入显式选为该文本。正式版本恢复自动化输入，不能遗留固定测试文本。

## 6. 验收

- 多行、空行、引号、Emoji、普通大括号、内部空格保持正确；标签不出现在微信消息内。
- 缺失/重复标签、空用户名、纯空白消息停止；平台阻止保留标签冲突。
- 不存在好友导致单次失败后，验证后续独立邮件是否继续触发。
- 记录设备/iOS/微信版本及锁屏/解锁结果。Apple 说明邮件自动化可配置自动运行，但这不证明微信动作无需交互，参见 [Apple 个人自动化说明](https://support.apple.com/guide/shortcuts/enable-or-disable-a-personal-automation-apd602971e63/ios)。
- 页面分别显示“邮件已发送”和快捷指令“微信发送成功”反馈，并分别记录时间；不推断对方已读。
